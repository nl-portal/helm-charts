# nl-portal-backend 3.2.2

App version: NL Portal `3.1.3`. Supports NL Portal 3.1.x.

## Breaking changes

- Templating fails when `settings.services.payment.direct.enabled` or `settings.services.payment.ogone.enabled` is set without `settings.services.taak.enabled`. NL Portal 3.1.3 fixes [GHSA-cvgw-7m2x-4g74](https://github.com/nl-portal/nl-portal/security/advisories/GHSA-cvgw-7m2x-4g74) and [GHSA-5869-gw29-cgpq](https://github.com/nl-portal/nl-portal/security/advisories/GHSA-5869-gw29-cgpq) by binding payments to an open payment task of the logged in user, so both payment modules now need the `taak` module and stay inactive without it. Enabling `taak` is safe on older 3.1.x versions too.

## Changes

- `appVersion: 3.1.3`.

## Deprecations

- `settings.services.payment.ogone`. NL Portal no longer supports Ogone e-Commerce and removes it in 4.0.0. Use `settings.services.payment.direct`.

## Migration

Only relevant with `settings.services.payment.direct.enabled` or `settings.services.payment.ogone.enabled`. Enable the `taak` module. It needs `objectenapi`, which payment already requires.

```yaml
# Before
settings:
  services:
    objectenapi:
      enabled: true
    payment:
      direct:
        enabled: true

# After
settings:
  services:
    objectenapi:
      enabled: true
    taak:
      enabled: true
      properties:
        typeUrl: https://objecten.example.nl/api/v2/objecttypes/<uuid>
    payment:
      direct:
        enabled: true
```

Payments without a task are no longer supported by the NL Portal payment API. See the NL Portal 3.1.3 release notes.
