# nl-portal-backend 4.0.0

App version: NL Portal `4.0.0`. Supports NL Portal 4.0.x.

Upgrading? See [Migration](4.0.0-migration.md).

## New features

- **Frontend features**\
  `settings.frontend.{toggles,properties,theme,modulesWhitelist}` sets the frontend's feature toggles, properties, theme and module whitelist. NL Portal serves them to the frontend through `GET /api/public/frontend`.

- **Ping endpoint**\
  `settings.app.support.pingEndpoint.enabled` enables `GET /api/public/ping`, a plain-text endpoint for monitoring tools.

- **Actuator security**\
  `settings.app.security.actuator.jwksURI` sets the realm whose tokens may call actuator refresh and restart, such as the Configuration Panel's notify client. Optional `issuerURI` also checks the token's issuer. `authoritiesClaimExpression` and `authorities` set where the roles are read and which role is needed.

- **Configuration Panel encryption**\
  `settings.app.features.configurationPanel.encryption.{enabled,key}` turns decryption of the Configuration Panel's values on or off and sets the panel's key.

- **Verificatie**\
  `settings.services.verificatie` configures the Verificatie module. `properties.url` is required when it is enabled.

- **Klantcontacten per register**\
  `settings.services.openklant2.properties.klantContactCodeRegister.{zaak,product}` only shows klantcontacten linked to objects in that register, for zaken and for producten.

- **Bewoning for selected cities**\
  `settings.services.haalcentraal2.properties.allowedCitiesForBewoning` is a comma-separated list of cities for which bewoning is shown.

- **Direct payment: credit card and number of payments**\
  `settings.services.payment.direct.properties.configurations.belastingzaken.{creditcardEnabled,allowedNumberOfPayments}` allows credit card payments (NL Portal default: off) and sets the number of payments allowed per payment request (default: 1).

- **Payments started on 3.x**\
  `settings.services.payment.direct.properties.acceptLegacyAmountRounding` accepts payments started on NL Portal 3.x and finished after the upgrade. Removed in NL Portal 5.0.

- **Document whitelists for all Documenten APIs**\
  `settings.services.documentenapis.properties.{vertrouwelijkheidsaanduidingWhitelist,statusWhitelist}` sets which confidentiality levels and statuses of documents are shown. Empty keeps NL Portal's defaults.

New optional values render only when set, so NL Portal's defaults apply otherwise.

## Fixes

- **Frontend works with custom unsecured endpoints**\
  `settings.app.security.endpoints.unsecured` renders only when set, so NL Portal's default `/api/public/**` survives. The 4.0.0 frontend loads its features from `/api/public/frontend` without a token. If you set the value, include `/api/public/**` yourself.

- **Unset values no longer override NL Portal's defaults**\
  These render only when set:
  - `settings.services.haalcentraal2.properties.brpFields`. Before, the empty value replaced NL Portal's default field set with an empty list.
  - `settings.app.security.cors`, rendered only when `path` is set. Before, the empty values replaced NL Portal's default (`/**` with `*` for headers, origins and methods) with a mapping that matched nothing.
  - `settings.services.documentenapis.properties.configurations.openzaak` and `dummydoc`, each rendered only when its `url` is set. Before, a configuration with an empty `url` matched every document URL.
  - `settings.services.haalcentraalHr.properties.ssl.*`. Before, the empty values gave HR an empty client certificate.
  - `settings.services.payment.direct.properties.webhookUrl`, `customTemplateUrl` and `configurations.belastingzaken.{language,currency}`. Before, these sent empty values to the PSP instead of NL Portal's defaults (`nl_NL`, `EUR`).
  - `settings.services.openklant2.properties.digitalAdressenReferentie`.

- **Taak object type reaches NL Portal**\
  Taak now reaches NL Portal through `settings.services.taak.properties.objectTypeUrl`.

- **Haal Centraal HR toggle for the gemachtigde query**\
  `NLPORTAL_CONFIG_HAALCENTRAALHR_ENABLED` is rendered next to `NLPORTAL_CONFIG_HAALCENTRAAL_HR_ENABLED`, from the same value. NL Portal 4.0.0 reads it for the gemachtigde query and the frontend module list.

## Breaking changes

- **New image name**\
  The default `image.repository` is now `ghcr.io/nl-portal/nl-portal-backend`. NL Portal 4.0.0 dropped the `-app` infix from its image names, and the old `nl-portal-app-backend` image has been archived. While `image.repository` still ends in the old name, `helm install` / `helm upgrade` print a warning with the chart notes. Templating does not fail, so mirrors and own builds under the old name keep working.

- **Bring your own Keycloak and database**\
  The chart no longer ships the Bitnami `postgresql` and `keycloak` subcharts. Before 4.0.0 they were installed with every release unless `tags` turned them off. The upgrade removes those StatefulSets; their PVCs remain.

- **Frontend values moved to this chart**\
  The frontend values moved here from nl-portal-frontend, under `settings.frontend`. See [Frontend values](4.0.0-migration.md#frontend-values).

- **Removed values fail templating**\
  Templating fails while any removed value is set, and the message lists every removed value it found, each with its replacement. See [Backend values](4.0.0-migration.md#backend-values).

- **Module validation changed**
  - Adds: `besluitenapi` requires `documentenapis` and `zakenapi`.
  - Changes: `payment.direct` requires `objectenapi` and `taak` (was `objectenapi`). In 4.0.0 payments only run through taken.
  - Drops: the `payment.ogone` rule.

- **Documenten API configurations need an RSIN and document type**\
  `rsin` and `documentTypeUrl` are now required for every `documentenapis` configuration whose `url` is set; templating fails without them. `dummydoc` gets both keys.

- **Actuator access is opt-in**\
  Only `/actuator/health` is open; other actuator endpoints, such as the Configuration Panel's `refresh` and `restart`, need `settings.app.security.actuator.jwksURI`.

- **Configuration Panel encryption key required**\
  With `settings.app.features.configurationPanel.enabled`, `settings.app.features.configurationPanel.encryption.key` is required unless `encryption.enabled` is `false`. Templating fails without it, unless `existingSecret` is set.
