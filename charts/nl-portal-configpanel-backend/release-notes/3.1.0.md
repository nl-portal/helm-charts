# nl-portal-configpanel-backend 3.1.0

App version: Configuration Panel `2.1.0`. Supports Configuration Panel 2.0.x and 2.1.x.

## New features

- `settings.app.security.api` configures the optional REST API role check from Configuration Panel 2.1.0:
  - `authoritiesEnabled` renders `CONFIG_SECURITY_API_AUTHORITIES_ENABLED`. Off by default; any valid token keeps access.
  - `authorities` renders `CONFIG_SECURITY_API_AUTHORITIES`, the comma separated roles that give access. Default `ROLE_ADMIN`.
  - `jwtAuthoritiesClaimName` renders `CONFIG_SECURITY_JWT_AUTHORITIES_CLAIM_NAME`, the SpEL expression for the claim holding the roles. Default `['realm_access']['roles']`.
  - An empty `authorities` or `jwtAuthoritiesClaimName` is not rendered, so the app default applies.
- Templating rejects `authoritiesEnabled: true` when the deployed Configuration Panel version is older than 2.1.0, because older versions ignore the setting and leave the API open. The version comes from `image.tag`, falling back to the chart `appVersion`. A tag that is not a semantic version, such as `latest` or a digest, cannot be checked and is left alone.

## Changes

- `appVersion: 2.1.0`. Configuration Panel 2.1.0 also updates the container base images with security updates.

## Migration

None. The role check is off by default.

```yaml
# Turning the role check on
settings:
  app:
    security:
      api:
        authoritiesEnabled: true
        authorities: "ROLE_ADMIN"
```
