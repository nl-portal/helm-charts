# nl-portal-configpanel-backend 4.0.0 migration

Depends on: upgrade before nl-portal-backend 4.0.0. Its database migration copies keys NL Portal 4.0 reads, so upgrading the portal first loses those settings. NL Portal 3.x can't read encrypted values: keep encryption off until every portal on the panel runs 4.0, and turn it on in nl-portal-backend before this chart.

Panel 3.0.0 serves NL Portal 3.x and 4.0 at the same time. Its database migration copies the theme and document whitelist keys to their 4.0.0 names. Delete the old keys listed in the panel's notice once every portal runs 4.0.

1. **Give panel users the admin role**\
   Give them `ROLE_CONFIG_PANEL_ADMIN`, or set `settings.auth.authorities`.

2. **Turn encryption off for now**\
   Set `settings.app.encryption.enabled: false`, and generate the key you'll use later (`openssl rand -base64 32`).

3. **Set up the notify client**\
   With `settings.app.notifyEnabled: true`, set `settings.app.notify.client.*`. Notify to a 3.x portal fails (logged as a WARN); saves still work.

4. **Upgrade**\
   Upgrade together with nl-portal-configpanel-frontend 4.0.0. Enter the Open Product settings again.

5. **Turn on encryption**\
   Once every portal on the panel runs 4.0 and nl-portal-backend has the key, set `settings.app.encryption.key` and remove `settings.app.encryption.enabled: false`. On restart the panel encrypts its stored values.

6. **Delete the old keys**\
   Delete the old keys listed in the panel's notice.

## Values

| Value | Default | Required |
| --- | --- | --- |
| `settings.auth.authorities` | empty: `ROLE_CONFIG_PANEL_ADMIN` | no |
| `settings.auth.authoritiesClaimExpression` | empty: `['realm_access']['roles']` | no |
| `settings.app.security.allowedKeyPrefixes` | `null`: `nl-portal.config.,nl-portal.frontend.`; an empty value fails templating | no |
| `settings.app.notify.client.tokenUri`, `.clientId` | empty | when `notifyEnabled` |
| `settings.app.notify.client.clientSecret` | empty | when `notifyEnabled`; with `existingSecret`, key `CONFIG_NOTIFY_CLIENT_SECRET` |
| `settings.app.notify.client.scope` | empty | no |
| `settings.app.notify.connectTimeout`, `.readTimeout` | empty: `5s`, `10s` | no |
| `settings.app.encryption.enabled` | `true` | no |
| `settings.app.encryption.key` | empty | when encryption is on; with `existingSecret`, key `CONFIG_ENCRYPTION_KEY` |

```yaml
# Panel (nl-portal-configpanel-backend)
# Before
settings:
  app:
    notifyEnabled: true
    notifyList: http://nl-portal-backend

# After, while a portal on the panel still runs 3.x
settings:
  app:
    notifyEnabled: true
    notifyList: http://nl-portal-backend
    notify:
      client:
        tokenUri: https://keycloak.example.com/realms/<panel realm>/protocol/openid-connect/token
        clientId: nl-portal-configpanel
        clientSecret: <secret>
    encryption:
      enabled: false

# After, once every portal on the panel runs 4.0
settings:
  app:
    notifyEnabled: true
    notifyList: http://nl-portal-backend
    notify:
      client:
        tokenUri: https://keycloak.example.com/realms/<panel realm>/protocol/openid-connect/token
        clientId: nl-portal-configpanel
        clientSecret: <secret>
    encryption:
      key: <the same key as nl-portal-backend>
```
